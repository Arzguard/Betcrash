Fairness

How crash points are determined — and how you can verify every round yourself.

🧪
Simulation mode. The game server isn't connected yet, so rounds you see right now are generated in your browser and clearly labelled — there is nothing to verify yet. When the server goes live, this page will switch to "live" automatically and the scheme below takes effect.

What "provably fair" means

A crash round is provably fair when the crash point is fixed before the round starts — by the house, without knowing your bet — and you can verify afterwards that the number you saw was the one that was committed. Neither side can cheat: the house can't steer rounds after seeing bets, and you can't fake a win.

How crash points will be generated (server)

Every round uses three inputs:

  • Server seed — a random 64-character hex string, generated and kept secret by the server during the round.
  • Client seed — a string you can choose (and change any time) from your account. Until you change it, the same client seed is reused so your results stay verifiable.
  • Nonce — a counter that increases by 1 every round you play, so the same seeds can never produce the same round twice.

Before the round, the server publishes the SHA-256 hash of the server seed (a "commitment" — 64 hex characters that can't be reversed). The crash point is then derived with an industry-standard formula (the same one used by Bustabit and similar sites), with a 3% house edge:

h     = parseInt( sha256(serverSeed + clientSeed + nonce).slice(0, 13), 16 )
e     = 2 ** 52 / h
crash = max(1, floor(e * (1 - houseEdge) * 100) / 100)   // houseEdge = 0.03

The 3% house edge means that over many rounds the game returns 97% of stakes — that's the built-in advantage, visible to everyone, not hidden.

Verifying a round

  1. Before the round starts, note the server seed hash, your client seed and the nonce (shown on the round screen).
  2. After the round crashes, the server reveals the server seed.
  3. Run the formula below (or any independent verifier) and confirm the result matches the crash point you saw.

Paste this into your browser console while on the game page — it needs no external tools:

async function verifyCrash(serverSeed, clientSeed, nonce, houseEdge = 0.03){
  const buf    = new TextEncoder().encode(serverSeed + clientSeed + nonce);
  const digest = await crypto.subtle.digest('SHA-256', buf);
  const hex    = [...new Uint8Array(digest)].map(b => b.toString(16).padStart(2,'0')).join('');
  const h      = parseInt(hex.slice(0, 13), 16);
  const e      = 2 ** 52 / h;
  return Math.max(1, Math.floor(e * (1 - houseEdge) * 100) / 100);
}
verifyCrash('<server seed>', '<client seed>', <nonce>).then(console.log)

Seed rotation

The server seed is replaced after every 1,000 rounds, and the previous seed is revealed at the moment of rotation. This guarantees the house can never selectively "re-seed" after a bad result.
